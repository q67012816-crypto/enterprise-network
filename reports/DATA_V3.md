# 链路预测数据版本 v3（`linkpred/data_v3/`，2026-11-03）

**状态：** 新数据版本已建成，单元检查全部通过。**还没有在 v3 上跑任何模型。** 之前所有链路预测结果（interim、Stage 1B、1C、Stage 2）都基于 v2（`data_a2_apionly/`），需要在 v3 上重跑。2024→2025 测试年此前已被多次查看，所以在 v3 上得到的测试数字仍然只是探索性的。

## 1. 为什么要做 v3：v2 的正例里有大量“并不新”的关系
逐条检查 v2 的每个正例在 t+1 年的出资行，发现很多关系在 t 年就已存在，只是 t 年没有被观测到：

| v2 正例 | 2021→22 训练 | 2022→23 训练 | 2023→24 验证 | 2024→25 测试 |
|---|---|---|---|---|
| 全部 | 260 | 290 | 303 | 339 |
| 改名造成：t 年表中用当时的名称列出，但改名公告在 C_t 之后，所以 t 年匹配不上 | 10 | 6 | **62** | 0 |
| 期初已持有、首次取得 ≤ t，但投资方 t 年的表里没有列出 | 69 | 79 | 69 | 52 |
| 期初余额 > 0 但首次取得在 t+1 年（字段自相矛盾） | 4 | 6 | 17 | 11 |
| t 年名称可匹配，但被筛选条件排除 | 3 | 1 | 0 | 2 |
| 没有证据表明早已存在 | 174 | 198 | **155** | 274 |

v2 的标签噪声各年差别很大：验证年约 49% 的正例可疑，测试年约 19%。

## 2. v3 的三处修改（`linkpred/src/build_v3.py`）
其余规则全部沿用 v2：合格性、持有条件、as-of 截止、A2 名称规则、A4 只用 API 规则、财务特征、行业和市场（当前值）、负采样（每个正例 100 个、种子 20261103）。

1. **名称按“当时有效的名称”解析（`--names-any yes`）。** 曾用名表不再要求改名公告在 C_t 之前。改名公告只用来确认“这个旧名称就是这家公司”，不带入任何业务信息；投资行本身仍须在 C_t 之前披露。其他要求不变：曾用名必须唯一，不能与其他公司的现名冲突，仍然不做模糊匹配。
2. **去掉不带括号的脚注标记（`--a2b yes`）。** 例如 `TKG휴켐스 *4`，只匹配“空白 + 星号 + 数字”这种结尾。曾用名查找也改用去掉尾部标记后的名称。
3. **“新边”必须真的是新关系（`--newness yes`）。** 首次出现的点对，要求 t+1 年的出资行满足以下任一条件：
   - 期初未持有：期初数量、账面价值和比例都为 0 或空，标为 `new_opening_zero`；
   - 首次取得日在 t+1 财年内，标为 `new_acquired_in_year`。这类行期初余额 > 0、与取得日矛盾，按新关系计，并在 `new_evidence` 列里标出来。

   只要任一条出资行显示“期初持有，且首次取得早于本财年（或取得日未知）”，就判为**早已存在**。这类点对不作正例，也不作负例（它们属于 G_{t+1}，本来就会被排除在负例之外），单独写入 `preexisting_pairs.csv`。

**回归检查：** 三个开关都关闭时，`build_v3.py` 的输出与 `data_a2_apionly/` 逐字节一致。`history_undirected.csv` 只有行顺序不同，内容完全相同。

### 3.3 残余噪声（用同一套检查方法重查 v3）
- 改名造成的、以及“t 年已持有但表里没列”的可疑正例：各年都是 **0**。
- 剩下的只有字段自相矛盾、按新关系计的行：4 / 3 / 9 / 11（占 2%–5%），已在 `new_evidence` 列标出，可以做敏感性分析。

### 3.4 单元检查（`data_v3/unit_checks.csv`，全部通过）
- 特征披露日 ≤ C_t；
- 正例不在 H_t 中，也不在 G_t 中，但都在 G_{t+1} 中；
- 负例不在 H_t ∪ G_{t+1} 中；
- 早已存在的点对既不是正例也不是负例；
- 每个点对的两端在 t 年和 t+1 年都合格；
- 每个正例恰好有 100 个负例；
- 每个正例都有“新关系”证据。

## 4. 影响和注意事项
1. **之前的模型结果都要在 v3 上重跑**，包括 M0–M3 和组内指标。原来的结论（M3 没有可靠超过 M1 等）在 v3 上是否成立，**未验证**。
2. **样本更小了：** 验证集只有 164 个正例，冷启动组（一端孤立）只有 58–80 个，两端孤立在所有年份都少于 30 个。冷启动分析的统计功效比之前估计的更低。
3. **可以写进论文的发现：** v2 首次出现的边中有 19%–49% 的关系其实早已存在。公开披露数据的观测缺口很大，而且逐年不同，这本身可以支撑论文的“问题”部分。
4. **协议：** v3 的规则还没有写进 `protocol.md` 或 `protocol_confirm.md`。如果确认性测试（FY2025→26）要用 v3，需要在 2027 年 5 月之前以修订的形式追加。这需要 Mingsen Zhang 决定。
5. **仍未解决的限制：**
   - 行业和市场用当前值；
   - 候选集要求两端在 t+1 年也合格（用到了未来信息）；
   - 图只包含上市公司之间的关系；
   - 曾用名与另一家公司后来采用的名称相同时可能误匹配（罕见，未验证）；
   - 期初余额和首次取得日这两个字段本身的质量未逐条人工核对（未验证）。
