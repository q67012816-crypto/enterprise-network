## 2. M3 方法
- **数据：** `linkpred/data_a2_apionly/`，即 A4 方案 a，所有年份只用 API 规则建图。点对、负例和特征口径都与 M0–M2 相同。
- **模型：** GraphSAGE，均值聚合，无向 G_t。节点特征与 M1 相同（财务特征，加行业和市场 one-hot）。
- **网格（§7）：** hidden {64,128} × 层数 {1,2} × lr {1e-3,1e-2} × dropout {0,0.3} × 解码器 {dot, MLP}，共 32 种配置，每种跑种子 1–5，合计 160 次。
- **训练设置：** Adam，wd=0，最多 200 轮，按验证 AP 早停，patience 20。实现为纯 PyTorch 2.15 CPU，全批量训练，总共约 7 分钟。
- **选配置：** 按 5 个种子的平均验证组内 AUC（A6 / protocol_confirm）。选中 `h128_l2_lr0.01_do0.3_mlp`，验证组内 AUC 0.6926，验证 AP 0.0402。如果按验证 AP 选，结果是同一个配置。
- **测试：** 只运行一次。分数是 5 个种子预测的平均。各种子单独的测试 AP 为 .039 / .036 / .036 / .037 / .032。
- **评估：** 组内指标的计算是每个正例在自己的 101 个候选中排序，并列取期望秩。区间来自按投资方聚类的配对 bootstrap，1000 次，`default_rng(20261103)`，所有模型共用同一组重抽样，取 95% 百分位区间。M1、M1+scores、PA 用的是 Stage 1C 冻结的测试分数（`out_1c_a4/test_scores.csv`）。核对：本次得到的 M1+scores − M1 组内 AUC 为 +.012 [+.005, +.020]，与 Stage 1C 一致。

## 4. 与协议的偏离、问题和未验证事项
1. **选配置准则：** §7 原文按验证 AP 选；本阶段按 A6 / protocol_confirm 改为验证组内 AUC。两种准则选出的是同一个配置，所以对结果没有影响。早停仍按 §7 用验证 AP。
2. **测试 AP 的口径：** §7 写的是“5 个种子预测的 AP 平均”；本报告表里的 AP 是 5 种子平均分数的 AP（.040），bootstrap 也用平均分数。各种子 AP 的均值为 .036，已在第 2 节列出。
3. **MRR 和 Hits@10 的口径：** 这里指的是组内指标（A5，101 个候选）。§4 的全候选排序 Hits@10/50、MRR **没有为 M3 计算**，因为需要对每个投资方的全部合格企业打分。这一项尚未完成。
4. **分组判定：** 用正例自身的 group。分组 AP 只用该组正例及其各自的负例。
5. **MLP 解码器的形式**（[h_u⊙h_v, |h_u−h_v|] 接两层网络）和 G_t 中合格集以外节点的处理（这些节点保留，特征按缺失值填补）属于执行者的选择，§7 没有规定。
6. **非确定性：** 训练在 CPU 上进行，固定了种子。在其他硬件或其他线程数下重跑，数字可能有微小差异（未验证）。
7. **依赖：** 在 box 上安装了 torch 2.15.0+cpu（用 `pip --break-system-packages`）。没有新的 DART API 调用。
8. **其他：** 行业和市场用的是当前值（A3），API 匹配会漏边，存在幸存者偏差，这些都与 Stage 1C 相同。
9. **git：** 本仓库的 user.email 已设为 q67012816@gmail.com（仓库级设置）。没有 push。
